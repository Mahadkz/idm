# IDM browser behavior contracts and replacement acceptance

Reviewed 2026-10-12. Scope is the supplied Integration Module 6.43.1, installed Chromium/Edge/Firefox packages, the existing original-source component probes, and the current independently written XDM bridge. This is a source-observable contract inventory. It does not establish every host configuration, desktop pipe field, browser race outcome, website adapter, or hidden native behavior. Source observations, mocked experiments, original Wine execution, and XDM tests are kept distinct.

## Evidence identities

`B` means `/tmp/xdm-idm-inspection-3ifum5xo/background.js`; `C` means its `content.js`; `D` means its `document.js`; `R` means its `captured.js`; `W` means its `welcome.js`. These temporary files are analysis inputs and can disappear. The exact packaged background SHA-256 and manifests are persisted in [browser_packages.json](analysis/runtime_final/browser_packages.json). Source line numbers refer to the minified Chromium 6.43.1 source, so symbol names are more useful than line numbers. No proprietary implementation is included in product source.

`P` means [extension_contract_results.json](analysis/browser_media/extension_contract_results.json), produced by [the original-source mock probe](analysis/extension_contract_probe.mjs): 15 assertions passed, plus one 30 ms disconnect observation. `N` means [native function inventory](analysis/browser_media/native_function_inventory.json) and [host experiment](analysis/browser_media/native_host_result.json). `L(key)` means [language catalog](analysis/idm_language_catalog.json), which is UI/message evidence rather than proof of a runtime caller.

`XB`, `XC`, and `XP` mean the current replacement's [background](../extensions/chromium/background.js), [content script](../extensions/chromium/content.js), and [popup](../extensions/chromium/popup.js). `T1` is [extension_handoff.mjs](../tests/integration/extension_handoff.mjs), `T2` is [chromium_real.mjs](../tests/integration/chromium_real.mjs), and `T3` is [media_clear.py](../tests/integration/media_clear.py). Existing passing tests cover their fixtures; tests described as required below have not passed merely because they appear in this document.

## Single-use resources and replay boundary

Language messages21181–21185 expose requests that may work only once and describe trying IDM before the browser. That is evidence of a distinct capture/context problem, not proof of a general replay algorithm. Original source can act at request/response hooks or ask for cached response text; the original Wine HTTP run started with GET rather than HEAD. Current XDM direct-file engine uses HEAD, a byte-range probe and subsequent GET/Range transfers. A token that permits one request can therefore be consumed before its actual transfer, even if browser interception is accepted. The replacement must classify replayability and reuse a successful initial response or choose a single-stream request when appropriate; no HEAD/probe step should be described as equivalent to the original lifecycle without a single-use fixture. POST acceptance also needs method/body semantics and explicit retry rules rather than only copying cookies. T2 handoff tests do not establish these properties.

## Browser-specific packaging and unverified boundaries

Chromium MV3 6.43.1 requests observation permissions plus DNR; its observed registrations do not request HTTP `webRequestBlocking`, so Firefox blocking returns must not be assumed to work there. Firefox MV2 6.43.1 actually registers blocking before-request, blocking before-send-headers and headers-received, and before-redirect; it has no downloads permission/onDeterminingFilename in the inspected package. Its downloader takeover must be tested as its own network cancellation/reply lifecycle. Firefox also uses privacy first-party isolation and idle APIs. Packaged Edge MV2 6.43.1 and legacy Chromium MV2 6.40.8.2 request webRequestBlocking, have persistent background arrangements and filename hooks, and use older content/helper delivery. These are package facts, not evidence that current browsers load each old package. XDM currently provides one Chromium MV3 adapter; a separate Firefox MV2 adapter now exists (`extensions/firefox`, `downloads.onCreated` pause/cancel/erase, non-blocking `webRequest`; mocked-tested, real-Firefox verification pending), and native Edge/Brave packaging/registration must be tested separately.

The original extension mock tests did not exercise negotiated real site rules, an actual browser's process/DNR/DOM events, native Windows integration, page capture hooks, overlay pixels, or successful original media muxing. XDM's real Chromium test verifies its own fixture handoff and daemon-down browser fallback, not original IDM integration. No browser or desktop GUI was launched on the user's display for this mapping.

**Closure criterion:** all 62 contracts above have original evidence, replacement state/difference and a required acceptance outcome. The static inventory closes observable Chromium registrations/dispatch/producer indices; cross-package hook differences are separately inspected. Host-supplied rules, numerical meanings not exercised, native OS outcomes and arbitrary real sites stay explicitly unverified. Feature mapping is complete for these recorded source surfaces; behavioral parity is still work to implement and test.
