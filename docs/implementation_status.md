# IDM feature parity: implementation status

This is a current-build checklist against the [bounded supplied-artifact audit](idm_audit_completion.md). The [coverage ledger](feature_coverage.md) maps every supplied dialog/control/menu identity; the [dynamic behavior review](idm_behavior_review.md) manually associates all 1,604 language entries with semantic sections and specifies 39 additional behavior contracts. These are mappings, not runtime parity. “Implemented” means code and local tests exist; it does not imply behavior on every website or native Windows validation. The original product's 105 dialog resources are cataloged in [the dialog ledger](analysis/idm_dialog_catalog.md); XDM uses its own visual design and assets.

The behavior mapping exposes priorities before broad feature expansion: single-connection resume, replay-safe probing, browser request context and ownership reconciliation, then independent queue start/order/retry semantics. Native Windows Chromium/Edge handoff and authenticated clear-media requests remain platform gates. GUI parity needs a virtualized task model and measured CPU/RAM against a Qt Widgets baseline. DRM decryption and copying proprietary code or assets are outside this project.
